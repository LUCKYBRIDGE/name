# 한자 다중 의미 레이어

이 폴더는 인명용 한자의 뜻을 **대표 훈 한 줄**로 축약하지 않고, 한자와 독음을 함께 키로 사용해 여러 의미를 보존한다.

## 파일
- `meaning-senses.csv`: 정확 훈음 관계 7,425개를 의미 단위로 전개한 전수 데이터
- `naming-meaning-curated.csv`: 작명에서 어떤 의미를 대표 설명으로 사용할지 사람이 검토한 예시·정책 레이어

## 현재 수치
- 정확 독음-한자 훈음 관계: 7,425
- 의미 항목: 13,046
- 2개 이상 의미를 가진 관계: 3,492
- 고유 한자: 7,150

## 핵심 구조
`meaning-senses.csv`의 기본 키는 `(hanja, legal_reading, sense_order)`다.

예:
- 祐 + 우 → 도울 우 / 다행할 우
- 優 + 우 → 넉넉할 우 / 부드러울 우 / 나을 우 / 결단성 없을 우
- 樂 + 낙·락·악·요 → 독음마다 의미 목록을 따로 유지

## 매우 중요한 한계
`meaning-senses.csv`는 libhangul의 `meaning_ko` 문자열을 쉼표 기준으로 **기계적으로 분리한 파생 데이터**다. 따라서 이것은 완전한 사전학적 의미 번호 체계가 아니다.

- 비슷한 뜻이 중복될 수 있다.
- 이체자·동자 설명이 의미처럼 포함될 수 있다.
- 용례·문법 기능·역사적 의미가 섞일 수 있다.
- '작명에 좋은 뜻' 여부는 이 파일만으로 자동 결정하지 않는다.

## 작명 앱 사용 순서
1. 법적 독음 확인
2. `meaning-senses.csv`에서 해당 독음의 모든 사전형 뜻 표시
3. 검토된 `naming-meaning-curated.csv`가 있으면 대표 작명 의미 후보 제시
4. 사용자가 선택한 의미를 `selected_sense_id`로 이름 후보에 기록
5. 선택한 의미를 바탕으로 작명 풀이 문장을 생성
6. 다른 사전 의미가 있으면 숨기지 않고 '다른 뜻'으로 함께 제공

사전에 없는 의미를 좋은 뜻처럼 새로 생성해서는 안 된다.

## 선택 의미 기록
작명 후보에서 실제로 중심으로 삼은 뜻은 전체 의미 데이터와 분리해 기록한다.

- 표준 객체: `name-meaning-selection.schema.json`
- 위험도 규칙: `semantic-risk-rules.csv`
- 일부 의미의 주의 유형: `sense-concern-curated.csv`
- 예시: `selection-examples.json`

핵심 필드는 `selected_sense_ids`, `selection_origin`, `naming_intent`, `semantic_risk`, `interpretation`이다.

**semantic_risk는 글자의 길흉 점수가 아니다.** 선택 근거가 유효한지, 같은 독음에 주의할 다른 뜻이 있는지 설명하기 위한 정보다. 부정적 다른 뜻이 하나 있다는 이유만으로 글자를 자동 탈락시키지 않는다.
