# 작명소·사주풀이 데이터 심화 로드맵

기준일: 2026-11-22

목표는 `LUCKYBRIDGE/name`을 단순 참고자료 모음이 아니라 **작명·이름분석·사주풀이 앱이 근거를 추적하면서 사용할 수 있는 검증형 데이터베이스**로 만드는 것이다.

## 원칙

1. 법적 사실, 사전 사실, 편집 작명 풀이, 전통 성명학, 사주 방법론, 실사용 통계를 섞지 않는다.
2. 학파에 따라 달라지는 값은 반드시 `method_id`를 붙인다.
3. 사전에 없는 길상 의미를 만들지 않는다.
4. 원자료가 이상해 보이면 자동으로 고치지 않고 source-quality hold로 보낸다.
5. 공식·학술·2차 출처의 신뢰도와 재배포 권리를 별도로 관리한다.
6. 앱에서 확정값으로 쓰기 전 `quality-gates.json`의 blocking 상태를 확인한다.

## P0 — 공개 작명 기능의 정확도

### 1. 작명 한자 의미 큐레이션

현재:
- 전체 의미 레이어: 7,150자 / 13,046 의미
- 사람 검토 작명 의미: 300자 / 652 의미

목표:
- 1차: 앱 우선 후보 100자 이상 — 달성
- 2차: 실제 작명에서 자주 검토할 핵심 300자 이상 — **300자 달성**
- 장기: 사용 빈도·요청 빈도에 따라 단계 확장

각 한자+독음의 **모든 문서화된 뜻**을 검토하고 다음으로 구분한다.
- `preferred_name_sense`
- `usable_name_sense`
- `contextual_dictionary_sense`
- `caution_other_dictionary_sense`

### 2. 현행 인명용 한자 공식 전수 대조

현재 후보 미러는 빠른 검색에는 사용할 수 있지만 현행 법적 전체목록이라고 단정하지 않는다.

완료 조건:
- 현행 법원 목록을 재배포 조건을 침해하지 않는 방식으로 정규화
- 후보 미러와 독음+자체 단위 diff
- 추가/삭제/허용자체 차이 보고서
- 앱의 법적 flag는 이 검증 계층을 통과한 경우에만 확정 표시

### 3. 성명학 method 실제 계산표

현재 13개 method를 구분했고, 초성 중심 통용형 14개 기본 초성 배속표와 Unihan `kRSKangXi` 기반 강희 부수-잔획 기술 재구성 method를 구축했다. knolname2의 214부수 자원오행·84자 override·11종 원획 delta는 DB로 이전했지만 외부 학파 출처가 없는 legacy 구현이므로 확정 판정에는 사용하지 않는다. 기존 knolname의 81수리 81행도 회귀용 격리표다. 구마사키 81수와 채침·홍범 81수는 서로 다른 역사 method로 분리했으며, 구마사키 원전은 확인했으나 1~81행 전사는 아직 검증 대기다. 또한 2024년 KCI의 214부수 자원오행 연구를 별도 method로 등록했으나, 학회 저작권 때문에 논문 표 214행은 그대로 복제하지 않고 독립 재구성 또는 이용허락 확보 후 내장한다. 다음은 출처 연결 method별 실제 계산 데이터다.

우선 구축:
- 발음오행 자모 배속표
- 자원오행 배속 기준 및 한자별 예외
- 원획수 계산 규칙과 변형부수 보정
- 원형이정 격 계산식
- 81수리 1~81 해석표

중요: 서로 다른 학파의 표를 하나로 합치지 않는다.

## P0/P1 — 사주 계산 신뢰도

### 4. Golden vector 확대

현재 2026·2027 KASI 절기 경계 48개 회귀 벡터와 lunar-python 1.4.9 기반 64개 독립 구현 교차검증 벡터가 있다. lunar-python의 절기 clock은 베이징 시간 기준이어서 한국 golden 정답으로 취급하지 않는다.

추가할 사례:
- 입춘 전후 연주/월주 경계
- 각 절입 전후 월주 경계
- 자시 23시/0시 방법 차이
- 음력 윤달
- 대한민국 DST 시행기
- 1954~1961 표준시 UTC+8:30 시기
- 진태양시 보정 전후
- 출생시각 미상 처리

독립적으로 검증된 만세력/오픈소스 구현과 교차검증하되 결과 불일치는 숨기지 않는다.

### 5. 절기 연도 범위 확대

신생아 작명뿐 아니라 기존 이름 분석을 위해 과거 출생연도도 검증해야 한다.
원자료 재배포보다 **공식/검증 가능한 절기값과 계산엔진의 회귀 벡터**를 우선 축적한다.

## P1 — 실제 이름 선택에 중요한 데이터

### 6. 이름 유행·실사용 통계

대법원 전자가족관계등록시스템의 `상위 출생신고 이름 현황`, `상위 개명신고 이름 현황`을 공식 1차 출처로 등록했다. 자동수집·대량재배포 조건을 재확인한 뒤 다음 지표를 구축한다.
- 연도별·성별 선호 이름 순위
- 최근 1년/5년/10년 변화
- 상승·하락 추세
- 신생아 이름과 개명 선호 이름의 구분

인기 순위를 길흉 점수로 사용하지 않는다.

### 7. 발음·실사용성 데이터

구조화 대상:
- 성+이름 연속 발음
- 표준 발음 변화
- 흔한 오인·철자 혼동
- 희귀 한자의 표시/입력 난이도
- 로마자 기본형
- 명백한 부정적 동음·속어는 출처와 시대성을 함께 관리

### 8. 성씨·본관·항렬

현재 상위 31성 코어는 확보했다.

추가 순서:
1. 31성 내부의 본관·파별 검증 깊이 향상
2. 신뢰 가능한 항렬표가 있는 본관/파부터 추가
3. 상위 31성 밖으로 단계 확장

항렬은 성씨만으로 추정하지 않는다.

## 품질 목표

전문 서비스에서 각 결과는 최소 다음 메타데이터를 가져야 한다.

- source_id 또는 method_id
- 검증 상태
- 적용 범위
- 최종 확인 필요 여부
- 편집 해석인지 원자료 사실인지
- 다른 학파/출처와 충돌하는지
- 앱에서 자동 추천에 사용할 수 있는지

완성도는 데이터의 양보다 **검증 가능성·출처 추적성·방법론 분리**를 우선한다.
