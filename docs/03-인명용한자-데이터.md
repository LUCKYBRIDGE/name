# 인명용 한자 데이터 설계

## 법적 판정 키
인명용 여부는 단순 문자 단위 boolean이 아니다.

권장 키: `(character, reading, legal_category, valid_from, variant_relation)`

법원 조회의 지정 독음과 별표 1·2 허용자체를 분리한다.

## 현재 상태
- 후보 검색: 2024-07-16 대법원 조회 기반 제3자 미러
- 현행 공식 조회/PDF 위치: 확인 완료
- 현행 공식 전체 목록과 후보 미러의 행 단위 diff: 미완료

따라서 후보 미러만으로 현재 출생신고 가능 여부를 일괄 확정하지 않는다.

## 공식 전수 대조
입력 규격: `data/hanja/official/official-reading-character.template.csv`

```bash
npm run audit:official-hanja -- data/hanja/official/official-reading-character.csv data/hanja/audit/official-diff.json
```

비교는 독음+Unicode 관계를 기본으로 하며 대법원 보도자료의 총 글자 수와 저장소 코드포인트 수를 숫자만으로 동일시하지 않는다.

## 의미·획수
- 의미: `meaning-senses.csv`의 한자+독음별 전체 의미
- 작명 선택: `selected_sense_ids`와 `naming_intent`
- 획수: Unicode 기술 획수와 method별 성명학 획수 분리

## 품질 테스트
중복, Unicode 정규화, 다른 독음의 의미 혼입, 허용자체 관계, 공식판과 미러 차집합, 기준일·출처 버전을 검사한다.
