# 연결 프로젝트에서 NAME 데이터 사용하기

작명·이름 분석·사주 앱의 동기화는 빌드나 배포 준비 단계에서 실행한다. 원본 `LUCKYBRIDGE/name`의 전체 커밋 SHA를 정한 뒤, 같은 커밋에서 [연동 매니페스트](../data/meta/integration-manifest.json)와 필요한 원본 파일을 가져온다. API로 파일을 받을 때는 파일 목록과 다운로드 URL 모두에 같은 커밋 SHA를 지정한다.

## 필요한 데이터 선택

| 기능 | 입력 경로 | 함께 적용할 기준 |
| --- | --- | --- |
| 한자 후보·작명 의미 | `data/hanja/normalized/reading-index.json`, `data/hanja/semantics/meaning-senses.csv`, `data/hanja/semantics/naming-meaning-curated.csv` | 한자와 독음의 조합으로 조회한다. 법적 허용 여부는 공식 조회로 확인한다. |
| 성씨·본관 | `data/surnames/surnames.csv`, `data/surnames/entries/<한자>.json`, `data/surnames/hangul-hanja-disambiguation.csv` | 동음 성씨를 구분한다. 본관 데이터는 공개 배포 범위와 행별 출처를 확인한다. |
| 성명학 | `data/methods/naming-method-registry.csv`, `data/methods/method-evidence.csv`, `data/methods/method-readiness.csv` | `method_id`를 유지하고 `final_scoring_ready`가 `true`인 방법만 최종 점수에 사용한다. |
| 사주 계산 자료 | `data/myeongri/`, `data/time/` | 절기 데이터의 연도 범위와 시간 기준을 유지한다. 사주 계산 엔진의 검증 범위는 품질 게이트에서 확인한다. |
| 등록·유행 통계 | `data/legal/name-registration-rules.csv`, `data/trends/` | 등록 판단에는 현행 공식 조회를 사용하고, 적재된 공식 통계가 있는 기간과 범위만 표시한다. |

각 프로젝트는 소비하는 파일 경로와 함께 `data/meta/schema-version.json`, `data/meta/quality-gates.json` 및 사용하는 출처·권리 메타데이터를 선택 목록에 포함한다. `schema_version`의 지원 여부와 사용하려는 기능이 각 게이트의 `blocking_for`에 해당하는지 확인한다. `manifest_version`은 매니페스트 형식에 대한 버전이다.

## 고정한 원본과 다운로드 검증

다음 예시는 검토한 커밋으로 체크아웃한 `name` 디렉터리에서 실행한다. 임시 디렉터리에 `data/`부터의 경로를 보존한다. GitHub에서 다운로드할 때도 파일의 원본 바이트를 유지하고, 한글 경로는 URL 세그먼트별로 인코딩한다.

```bash
NAME_COMMIT=$(git rev-parse HEAD)
NAME_STAGING=$(mktemp -d)

git archive "$NAME_COMMIT" \
  data/meta/schema-version.json \
  data/meta/quality-gates.json \
  data/hanja/normalized/reading-index.json | tar -x -C "$NAME_STAGING"

npm run verify:integration -- "$NAME_STAGING" \
  data/meta/schema-version.json \
  data/meta/quality-gates.json \
  data/hanja/normalized/reading-index.json
```

검증 도구는 실행한 `name` 체크아웃의 매니페스트로 각 파일의 바이트 수와 SHA-256을 대조한다. 지정 경로를 생략하면 매니페스트에 등재된 파일 전체를 대조한다. 매니페스트는 루트 `data/`의 연동용 CSV·JSON을 대상으로 하며, 원자료 디렉터리, 수작업 공식 대조 입력, 엑셀 조회본, 의미 선택 예제, 편집용 검토 목록, AI Studio 스냅샷은 범위 밖이다.

검증을 통과한 데이터로 앱용 산출물을 만들고 기존 스냅샷을 교체한다. 앱 산출물이나 배포 기록에 원본 저장소, 전체 커밋 SHA, `schema_version`을 남기면 연동 프로젝트별 원본 버전을 비교하거나 이전 버전으로 되돌릴 수 있다. 갱신에 실패하면 이전에 검증한 스냅샷을 계속 사용한다.

배포 파일을 선택할 때 [배포 정책](../data/meta/distribution-policy.csv), [출처별 권리](../data/meta/source-rights.csv), [앱 출처 표시](../APP_ATTRIBUTION.md)를 적용한다. 매니페스트의 SHA-256은 파일 무결성을 확인한다. 법적 판정, 계산 검증 수준, 재배포 조건은 각 기준 문서에서 확인한다.

## 공개 배포용 파일 묶음

공개·상업 배포에 원본 데이터 파일을 포함할 때는, 검토할 파일과 필요한 원문 고지만 새 디렉터리에 모아 검사한다. 현재 자동 검사에서 허용하는 데이터는 `data/methods/kangxi-radical-stroke-ranges.csv`다. 정확한 경로가 배포 정책의 `public_bundle_with_notices`에 등록돼 있어야 하며, 체크아웃의 원본과 바이트가 같고, 검토 당시의 데이터와 필수 고지를 함께 기록한 `reviewed_sha256`까지 일치해야 통과한다. 공개 규칙과 검토 보류 규칙이 동시에 적용되면 검증이 실패한다.

```bash
NAME_PUBLIC_STAGE=$(mktemp -d)
git archive HEAD data/methods/kangxi-radical-stroke-ranges.csv \
  COPYRIGHT.md THIRD_PARTY_NOTICES.md LICENSES/Unicode-3.0.txt | tar -x -C "$NAME_PUBLIC_STAGE"
npm run verify:public-data -- "$NAME_PUBLIC_STAGE"
```

이 검사는 원본 데이터 파일 묶음에 적용된다. 앱이 원본을 JSON이나 자바스크립트로 변환해 내보내면, 같은 출처·라이선스 고지가 최종 배포물에도 포함되는지 확인한다. 데이터나 필수 고지가 바뀌면 실제 포함 열·원천·이용 범위와 고지를 다시 검토한다. 검토 후 아래 명령이 출력한 지문을 배포 정책의 `reviewed_sha256`에 기록한다.

```bash
npm run verify:public-data -- --fingerprint data/methods/kangxi-radical-stroke-ranges.csv
```
자체 편집물의 이용은 별도 권리자 허락 범위를 따른다.

## 원본 유지보수

연동용 파일을 수정한 뒤 `npm run build:derived`로 매니페스트를 재생성하고 `npm run check`를 실행한다. GitHub Actions에서 매니페스트를 다시 생성해 커밋된 내용과 대조한다.
