# 앱의 출처·저작권 표시 규격

이 문서는 `LUCKYBRIDGE/name`을 사용하는 작명 앱에서 출처를 실제 UI에 어떻게 표시할지 정한 규격입니다.

## 1. 앱 전체에 필요한 화면

앱 메뉴 또는 하단에 **자료 출처·라이선스** 화면을 둡니다.

최소 구성:
1. 서비스 자체 설명 및 전통 명리·성명학 해석의 성격
2. 인명용 한자 오픈데이터 고지
3. KOSIS 성씨·본관 통계 출처
4. 한국천문연구원 절기 자료 출처
5. 제3자 오픈소스/데이터 라이선스
6. 법적 인명용 한자 최종 확인 안내
7. 제3자 기관 비보증 문구

기본문구는 `APP_ATTRIBUTION.md`를 사용합니다.

## 2. 결과 가까이에 출처를 표시해야 하는 경우

### 성씨·본관 인구
결과 카드 하단:
`출처: 국가데이터처 국가통계포털(KOSIS), 2015 인구주택총조사`

앱이 계산한 비율·순위·나머지 값에는:
`KOSIS 원자료를 바탕으로 앱에서 계산한 값`

### 본관 역사·시조·계통
한국민족문화대백과사전 항목을 근거로 표시하는 설명에는:
`출처: 「실제 항목명」, ⓒ한국민족문화대백과사전`

여러 출처가 충돌하면 하나의 사실처럼 합치지 말고 각각 표시합니다.

### 24절기
절기 시각 또는 사주 경계 설명 하단:
`출처: 한국천문연구원 달력자료/월력요항`

### 법적 인명용 한자
후보 데이터와 법적 확정값을 구분하고 다음 안내를 둡니다:
`출생신고 가능 여부는 대한민국 법원의 현행 인명용 한자 조회를 최종 확인하세요.`

## 3. 표시하지 말아야 할 방식

- 제3자 기관 로고를 허락 없이 서비스 로고처럼 사용
- “한국민족문화대백과 인증”, “KOSIS 공식 작명”, “법원 인증 작명”처럼 후원·보증으로 오인되는 표현
- 학술논문 문단이나 표를 결과 화면에 그대로 노출
- 권리 미확인 족보·계보 사이트 내용을 긴 원문으로 표시
- 출처 링크 없이 제3자 설명을 앱 자체 설명처럼 표시

## 4. 데이터에서 UI로 전달할 메타데이터

가능하면 결과 객체에 다음 필드를 함께 전달합니다.

- `source_ids`
- `source_title`
- `source_url`
- `rights_class`
- `attribution_required`
- `attribution_template`
- `broad_release_action`

이 값은 `data/meta/source-rights.csv`를 기준으로 생성합니다.

## 5. 지인용과 일반 공개의 차이

지인용이어도 오픈 라이선스의 고지 의무는 유지합니다. 다만 현재처럼 제한적으로 사용할 때는 앱에 원자료 파일·PDF·논문·이미지를 직접 포함하지 않고 구조화된 사실과 자체 설명을 사용하는 방식이 가장 안전합니다.

일반 공개 또는 수익화 전에는 `broad_release_action`이 `manual_review_before_embedding_or_republication` 또는 이에 준하는 값인 출처를 다시 점검합니다.
