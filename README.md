# NAME — 한국식 작명 데이터베이스·지식베이스

**목적:** 한국식 이름 추천·분석 앱과 AI가 한자, 사주·명리, 성명학, 실사용성 자료를 **근거와 방법론을 보존한 채 조회**하도록 지원하는 구조화 데이터베이스 + 지식베이스입니다.

웹앱 UI 자체보다 **정확한 원천 데이터, 계산 규칙, 검증 절차, 출처 관리**가 이 저장소의 핵심입니다.

## 현재 확보된 구조화 데이터

### 인명용 한자
- 2024-07-16 대법원 조회 기반 제3자 미러
- 독음-한자 관계 정규화 및 중복 제거
- 독음별 검색 인덱스
- libhangul 기반 정확 독음-한자 훈음 결합
- 정확 훈음 관계 7,425개를 13,046개 의미 항목으로 분해한 다중 의미 레이어
- 3,492개 복수 의미 관계를 보존하고, 작명용 대표 의미와 전체 사전형 뜻을 분리
- 작명 의미 사람이 검토한 레이어를 95개 한자·202개 의미로 확대(여전히 부분 커버리지)
- 원자료 뜻 문자열이 의심스러운 4건은 자동 수정하지 않고 source-quality hold로 별도 관리
- Unicode Unihan 파생 부수·기술 총획
- 통합 검색용 한자 마스터

**중요:** 후보 검색 데이터와 현행 법적 판정은 별개입니다. 실제 출생신고 가능 여부는 최신 대법원 조회와 현행 규칙으로 다시 확인합니다.

### 성씨
- 2015 인구주택총조사 순위 1~31위 **31개 성씨 코어 DB** 구축
- 기존 徐(13위) 외 30개 성씨 상세 JSON 추가
- 金·李·朴·崔·鄭·姜·趙·尹·張·林 등 상위 성씨의 정확 인구·순위 연결
- 조(趙/曺), 유(柳/劉)처럼 한글은 같고 한자가 다른 성씨를 별도 ID로 관리
- 李/이·리, 林/임·림, 柳/유·류, 梁/양·량 등의 독음·표기 차이를 보존
- 31개 성씨 발음 프로필과 로마자 규칙형 구축
- 기술 총획은 수리성명학 기본값과 분리하여 method_id 없는 자동 계산 차단
- 공식 보도자료의 대표 본관 20개 행을 별도 부분 데이터로 수록
- 徐는 본관 전체 합계·본관 역사 근거까지 상세 기준 레코드로 유지
- 나머지 30개도 각 상세 JSON에 대표 본관·시조/원조/중시조·근거등급·출처 충돌·주의사항을 구조화
- 31개 모두 `clan-history.csv`에 최소 1개 이상의 계통 연구 행을 가지며, 설화·족보 전승·학술 참고를 구분
- 31개 모두 2015년 남/여 성씨 인구와 주요 본관 최대 7개 + 계산 나머지 요약을 보유
- `clans-core-2015.csv` 223행은 각 성씨의 요약 합계가 성씨 전체 인구와 정확히 일치하도록 검증

## AI Studio 앱 스냅샷

`ai-studio/`에는 2026-11-14 AI Studio에서 내보낸 앱 소스와 당시 앱이 사용하던
LUCKYBRIDGE 데이터 복사본이 보존되어 있습니다.

- 앱: https://ai.studio/apps/23ccdd98-87ab-46ff-a866-7534f81997b3
- 스냅샷 설명: `docs/06-AI-Studio-앱-스냅샷.md`
- **현재 데이터의 기준은 `ai-studio/data/luckybridge/`가 아니라 저장소 루트의 `data/`, `knowledge/`, `workflows/`입니다.**

앱 스냅샷은 실제 앱 구조와 데이터 사용 방식을 추적하기 위한 기록으로 유지합니다.

## 데이터 원칙
- **법적 사실**, **재현 가능한 계산**, **전통적 해석**을 분리합니다.
- 학파별 규칙은 `method_id`로 분리하고 하나의 절대 점수로 합치지 않습니다.
- 외부 출처는 [data/meta/sources.csv](data/meta/sources.csv)의 `source_id`를 우선 사용합니다.
- Unicode 총획수는 특정 성명학 원획수와 동일시하지 않습니다.
- 데이터 개수는 문서별로 복제하지 않고 [dataset-stats.json](data/meta/dataset-stats.json)을 기준으로 합니다.
- 사주·성명학은 전통적 해석 체계이며 과학적으로 검증된 미래예측으로 표현하지 않습니다.

## 재생성·품질 게이트
- `data/meta/build-manifest.json`: 파생 파일의 입력·생성기·재현 가능 여부
- `data/meta/quality-gates.json`: 앱이 확정값으로 사용해도 되는 계층과 미완성 계층
- `data/meta/source-audit.csv`: 출처 라이선스 메타데이터 감사
- `data/hanja/official/`: 현행 대법원 한자표 전수 diff 입력 규격

현재 정규화 한자·독음 인덱스·다중 의미 레이어·출처 감사표는 원자료에서 정확히 재생성할 수 있습니다.

```bash
npm run check
```

현행 공식 인명용 한자 전체 행 대조는 아직 P0 품질 게이트로 남아 있으므로, 후보 미러를 현행 법적 전체목록으로 표현하지 않습니다.

## 검증
대표 검증 사례는 `tests/`에 있으며, 데이터 구조 무결성은 다음 스크립트로 점검할 수 있습니다.

```bash
npm run validate:data
```


## 라이선스·제3자 데이터
이 저장소는 자체 작성 자료와 제3자 데이터를 함께 사용합니다.

- 자체 작성 자료 권리 고지: `COPYRIGHT.md`
- 제3자 고지: `THIRD_PARTY_NOTICES.md`
- 개별 라이선스 원문: `LICENSES/`
- 데이터 경로별 라이선스 맵: `data/meta/license-map.csv`
- 출처·재배포 검토 상태: `data/meta/sources.csv`, `data/meta/source-audit.csv`
- 출처별 앱 사용·재배포·표시 규칙: `data/meta/source-rights.csv`
- 저작권·데이터 이용 정책: `COPYRIGHT_AND_DATA_USE.md`
- 현재 권리 감사 현황: `RIGHTS_AUDIT.md`
- 새 자료 추가 시 준수 규칙: `CONTRIBUTING.md`
- 앱 표시용 출처·라이선스 문구: `APP_ATTRIBUTION.md`
- 배포 범위 정책표: `data/meta/distribution-policy.csv`

현재 루트에는 저장소 전체에 적용되는 별도 `LICENSE`를 두지 않았습니다. 따라서
`THIRD_PARTY_NOTICES.md`는 제3자 데이터의 사용 조건을 기록할 뿐, 저장소의
자체 작성 코드·문서·스키마·편집 해석 전체에 별도의 오픈소스 라이선스를 부여하지 않습니다.

### 공개 저장소 주의

이 저장소는 현재 public이므로, 지인에게만 사용하는 앱이라도 저장소 안의 제3자 데이터는 이미 공개적으로 제공되는 상태입니다. 따라서 앱 사용자 수와 별개로 제3자 라이선스·출처표시·재배포 조건을 관리합니다.

광범위한 공개 또는 상업 배포 전에는 `data/meta/distribution-policy.csv`에서 재검토 대상으로 표시된 데이터, 특히 보조 출처가 섞인 `data/surnames/clans-core-2015.csv`와 행별 출처가 다른 본관 역사 데이터를 다시 확인합니다.
