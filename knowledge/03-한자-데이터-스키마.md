# 한자 데이터 레코드 스키마 (제안)

아래 JSON은 **데이터 구조 예시**이며 실제 한자의 사실 데이터가 아니다.

```json
{
  "character": "예시 한자",
  "unicode": null,
  "readings_ko": [],
  "meanings_ko": [],
  "radical": null,
  "strokes": [{"count": null, "standard": null, "source": null}],
  "variants": [],
  "legal_status": {
    "jurisdiction": "KR",
    "allowed": null,
    "verified_at": null,
    "source_url": null,
    "source_version": null
  },
  "naming_interpretations": [
    {"school": null, "element": null, "basis": null, "source": null}
  ],
  "verification_status": "unverified"
}
```

## 작성 규칙
- 미확인 값은 `null` 또는 빈 배열로 둔다. 추정값을 사실처럼 채우지 않는다.
- 획수는 숫자 하나로 통일하지 말고 기준별 복수 기록을 허용한다.
- 성명학 오행 분류는 글자 자체의 불변 속성으로 저장하지 않고 학파별 해석으로 저장한다.
- 원자료의 발행기관, 접근일, 개정 기준일, 이용 허락 범위를 기록한다.
- 법적 허용 여부는 날짜에 따라 바뀔 수 있으므로 기준일 없는 true/false를 사용하지 않는다.
