# 성씨 처리 원칙

작명에서 성씨는 이름자와 결합하여 전체 성명을 이루지만 **이름자와 같은 방식으로 평가하지 않는다.**

## 1. 한글 성씨만으로 한자를 확정하지 않는다
같은 한글 성씨에 서로 다른 한자가 존재할 수 있다. 예를 들어 '서'는 徐 외에도 다른 한자 성씨가 있으므로 가족관계등록부 등 사용자가 실제 사용하는 성씨 한자를 우선한다.

## 2. 성씨의 사전 뜻은 참고 정보다
徐의 훈이 '천천할 서'라는 사실은 한자 정보로 보존한다. 그러나 이를 이름자의 길상 의미처럼 점수화하거나 '느리다'라는 이유로 이름 전체의 품질을 낮추지 않는다.

성씨 의미를 사용하는 특정 성명학 method가 있다면 그 method의 규칙과 출처를 명시하고 별도 결과로 제시한다.

## 3. 성씨 획수는 method별로 처리한다
Unicode·사전의 기술 총획과 수리성명학의 원획/필획은 다를 수 있다.

- 기술 총획: 문자 메타데이터
- 성명학 적용 획수: method_id별 데이터

원격·형격·이격·정격 계산을 할 때 성씨 획수가 필요하면 해당 method의 획수 기준을 먼저 확인한다.

## 4. 본관은 가족 맥락이다
본관은 성씨와 함께 한국의 가계·친족 맥락을 이해하는 자료다. 다만 본관 자체를 이름의 길흉 점수로 자동 변환하지 않는다.

항렬자·돌림자·가족 전통을 사용자가 요청한 경우에만 관련 맥락으로 활용한다.

## 5. 통계는 기준시점을 붙인다
성씨 인구와 본관 인구는 조사 시점이 있는 통계다. '현재 인구'라고 표현하지 않고 예를 들어 '2015-11-01 인구주택총조사 기준'처럼 표시한다.

## 6. 로마자 표기는 참고와 실제 표기를 분리한다
국어의 로마자 표기법에 따른 규칙형을 제공할 수 있지만 실제 여권의 로마자 성은 기존 사용 이력·가족 표기·여권 규정을 따른다.

작명 앱은 기존 여권 표기를 임의로 바꾸도록 권하지 않는다.

## 7. 작명에서 성씨가 실제로 영향을 주는 항목
- 성+이름 전체 발음과 어감
- 음절 반복·연음·동음이의어
- 특정 성명학 method의 획수 계산
- 가족의 항렬자·돌림자
- 로마자 전체 이름의 읽기 편의

## 8. 성씨-이름 경계의 발음은 음절 구조부터 본다
성씨 자체의 종성이 있는지 먼저 확인하고, 그다음 이름 첫 음절과의 경계에서 실제 음운 변동 가능성을 본다.

徐의 한글 성씨 '서'는 **ㅅ+ㅓ, 종성 없음(CV)** 구조다. 따라서 성씨 종성 때문에 생기는 연음·비음화·유음화·받침 유발 경음화를 성-이름 경계에서 기본적으로 촉발하지 않는다.

다만 이것은 '모든 이름 조합이 같은 발음 난이도를 가진다'는 뜻이 아니다. 전체 이름의 반복감·동음이의·음절 리듬은 별도로 평가한다.

예:
- 서+진우: 성씨 종성 기반 변동 없음
- 서+연우: 성씨 종성 기반 변동 없음
- 서+서준: 음운 오류가 아니라 동일 음절 반복에 대한 실사용성 notice

반복 플래그는 자동 탈락이나 길흉 판정에 사용하지 않는다.

## 9. 본관 역사에는 근거 수준을 붙인다
본관별 시조·분파 정보는 통계와 성격이 다르다.

- 인구·본관 인구: 공식 통계
- 역사 인물·시조 서술: 학술 참고자료
- 문중의 분파·계통 전승: 공공 문화자료·족보 전승

이들을 하나의 동일한 '사실 등급'으로 취급하지 않는다.

徐 데이터에서는:
- 이천서씨 서신일: 한국민족문화대백과의 역사 인물 항목을 학술 참고 근거로 연결
- 달성서씨 서진: 지자체 문화·지역사 자료가 소개하는 시조 전승으로 기록
- 대구서씨 분파 관계: 공공 문화자료의 계통 전승으로 기록하며 독립적인 학술 검증 필요 상태 유지

구조화 데이터는 `data/surnames/clan-history.csv`의 `evidence_level`과 `caveat`를 따른다.
