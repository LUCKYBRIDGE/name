# 한자 다중 의미와 작명 해석 원칙

## 1. 한자는 하나의 뜻으로 고정되지 않는다
한 글자가 여러 뜻을 가질 수 있다. 이름에서는 그중 문헌·사전으로 확인되는 의미 하나 또는 여러 의미를 중심으로 작명 의도를 정할 수 있다.

다만 **없는 뜻을 만들어 붙일 수는 없다.**

## 2. 법적 독음과 사전 의미는 다른 레이어다
대법원의 인명용 한자 체계는 이름에 사용할 수 있는 한자와 독음의 법적 범위를 다룬다. 그것이 곧 하나의 작명 의미를 법적으로 지정한다는 뜻은 아니다.

국립국어원도 인명용 한자의 훈 부여 문제는 온라인가나다가 답할 수 있는 어문 규정·표준국어대사전 범위를 벗어난다고 안내한다. 따라서 법원 허용 독음과 사전 의미 출처를 분리한다.

## 3. 의미는 반드시 한자+독음으로 조회한다
다음 키를 사용한다.

`(hanja, legal_reading)`

같은 한자라도 독음이 달라지면 훈과 의미 목록이 달라질 수 있기 때문이다.

예:
- 樂(낙): 즐길 낙
- 樂(락): 즐거울 락, 즐길 락
- 樂(악): 풍류 악, 즐길 악
- 樂(요): 좋아할 요, 즐길 요

## 4. 네 층으로 분리한다

### A. 원자료 훈음
예: `祐 / 우 / 도울 우, 다행할 우`

### B. 의미 단위
- 도울 우
- 다행할 우

### C. 작명용 의미 선택
부모나 사용자가 어떤 의미를 이름의 중심 뜻으로 삼을지 고른다.

### D. 작명 풀이 문장
예: '주변과 서로 도우며 복된 삶을 살아가기를 바란다.'

D는 사전 뜻 그 자체가 아니라 C를 자연어로 풀어 쓴 **편집·해석 문장**이다.

## 5. 좋은 뜻만 골라 보여 주지 않는다
예를 들어 優에는 긍정적으로 쓰기 좋은 뜻뿐 아니라 현재 데이터에 '결단성 없을 우'도 있다.

앱은:
- 대표 작명 의미는 긍정적이고 자연스러운 뜻을 우선 제시할 수 있지만,
- 다른 사전 뜻은 숨기지 않고 확인 가능하게 해야 한다.

## 6. 의미 선택은 글자의 뜻을 바꾸는 것이 아니다
부모가 祐에서 '도울 우'를 중심 의미로 선택할 수 있지만, 그 선택 때문에 祐의 다른 사전 의미가 사라지는 것은 아니다.

따라서 데이터에는:
- 전체 의미 목록
- 선택한 의미 ID
- 작명 풀이
를 별도로 저장한다.

## 7. 자동 생성 금지
다음은 금지한다.
- 사전에 없는 길상 의미 추가
- 부정적·중립적 의미를 근거 없이 긍정 의미로 변환
- 다른 한자의 뜻을 비슷한 글자에 전이
- 독음이 다른 의미를 현재 이름 독음에 자동 결합
- 작명가의 수사적 풀이를 사전 정의처럼 표시

## 8. 출처의 성격
현재 전수 의미 레이어는 libhangul 훈음 데이터를 기반으로 한다. 국립국어원은 표준국어대사전·우리말샘의 한자 원어 정보 역시 여러 교육자료·한자사전을 바탕으로 기술되어 특정 단일 자료를 지목하기 어렵다고 설명한다.

따라서 장기적으로는 중요한 이름 후보 한자부터 복수 사전·고전 용례를 추가 교차검증하고, 검증상태를 별도 필드로 올리는 것이 적절하다.

## 9. 선택한 뜻도 작명 데이터로 기록한다
같은 한자라도 이름에서 어느 뜻을 중심에 두었는지는 작명 의도에 중요하다. 따라서 이름 후보나 확정 이름에는 다음을 별도로 기록한다.

- `all_sense_ids`: 해당 한자+독음의 전체 문서화 의미
- `selected_sense_ids`: 이 이름에서 중심으로 삼은 의미
- `selection_origin`: 부모/사용자 직접 선택인지, 앱의 제안인지, 기존 기록인지
- `naming_intent`: 왜 그 뜻을 골랐는지
- `semantic_risk`: 다른 뜻과의 관계 및 근거 문제
- `interpretation.text`: 선택 뜻을 자연스럽게 풀어 쓴 작명 문장

## 10. semantic risk는 탈락 점수가 아니다
위험도는 다음처럼 해석한다.

- `none`: 선택 뜻과 다른 뜻 사이에 특별한 주의가 없음
- `low`: 문법적·별개 어휘 의미 등 가벼운 안내 필요
- `medium`: 같은 독음에 직접 부정적으로 읽힐 수 있는 뜻이 있어 눈에 띄게 안내
- `high`: 선택한 뜻 자체가 작명 대표 뜻으로 부적합하거나 설명이 매우 필요
- `invalid`: 해당 한자+독음에 없는 뜻을 선택했거나 다른 독음의 뜻을 가져온 경우

`low~high`는 해당 한자를 자동 탈락시키는 등급이 아니다. 자동 차단은 원칙적으로 `invalid`에만 적용한다.

## 11. 기존 이름의 작명 의도를 추정하지 않는다
이름을 분석할 때 부모가 어떤 의미를 골랐는지 기록이 없다면 `selection_origin=unknown`으로 둔다. 앱이 보기 좋은 뜻 하나를 골라 '부모가 이런 뜻으로 지었다'고 단정해서는 안 된다.
