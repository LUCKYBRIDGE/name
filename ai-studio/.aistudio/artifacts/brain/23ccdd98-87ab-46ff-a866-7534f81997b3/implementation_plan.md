# 서씨(徐) 정통 성명학 개명 스튜디오 — 구현 계획

`LUCKYBRIDGE/name` 저장소의 방향성에 맞춰 **성씨 '천천히 서(徐)' 특화 규칙**, **사주팔자(만세력) 오행 분석**, **원획 81수리·음양·발음오행·자원오행 검증**, 그리고 **기존 이름 대비 개명 비교 리포트**를 하나로 통합한 개명 작명 도구를 구축합니다.

---

### 사용자 검토 및 핵심 결정 사항

> [!IMPORTANT]
> **`LUCKYBRIDGE/name` 비공개 저장소 접근 안내 및 데이터 연동 방식**
> - 확인 결과 `https://github.com/LUCKYBRIDGE/name` 저장소가 현재 **비공개(Private)** 상태로 설정되어 있어 외부 API로 내부 문서를 직접 읽을 수 없습니다.
> - **권장 진행 방식**:
>   1. **기본 탑재 엔진 우선 구축**: 정통 성명학 기준(천천히 서 `徐` 원획 10획·발음오행 金·자원오행 土/金 기준, 만세력 사주 오행, 81수리 길흉, 대법원 인명용 한자 사전)을 내장하여 즉시 개명 작명과 감정 리포트가 작동하도록 구축합니다.
>   2. **앱 내 '내 자료 가져오기(Knowledge Sync)' 내장**: 비공개 저장소를 굳이 공개로 전환하지 않아도, 로컬 PC에 있는 `name` 저장소의 `.md`, `.json`, `.csv`, `.txt` 파일을 드래그 앤 드롭으로 불러오거나 내용을 붙여넣어 **서(徐) 성씨 전용 규칙·선호 한자·불용문자 기준**을 즉시 덮어쓰고 영구 저장할 수 있게 만듭니다.
>   3. **선택 사항**: 만약 계획을 승인하시면서 저장소를 잠시 공개(Public)로 전환하시거나 핵심 정리 텍스트를 채팅에 붙여넣어 주시면, 초기 내장 데이터에 바로 병합해 드립니다.

- **핵심 사용자 흐름(기본값)**: 사주 입력 및 기존 이름 입력 → 사주 오행·용신 도출 → `서(徐)` 성씨 기준 최적 수리·발음·한자 후보 탐색 및 직접 조합 → 기존 이름 vs 새 이름 나란히 비교 감정 → AI 작명가 심층 해설.
- **시각 스타일(기본값)**: 한지(韓紙)의 온기를 담은 아카이브 페이퍼(`#FBF9F5`) 바탕, 먹색 텍스트(`#1C1917`), 인주(朱) 포인트(`#9A3412`)와 1px 헤어라인 경계선을 활용한 단아한 동양 인문·분석 스튜디오 스타일.

## 1. 서비스 개요 및 핵심 개념

- **무엇을 하는 도구인가**: 개명을 준비하는 분이 본인의 생년월일시(사주)와 기존 이름을 입력하면, 부족한 오행(용신/희신)과 **서(徐)씨 성씨의 고유 음양·획수·발음오행 구조**에 완벽히 부합하는 새 이름 후보를 찾고, 수리적·음운적·의미적 변화를 직관적으로 비교해 주는 전문 작명 워크벤치입니다.
- **대상 사용자**: `LUCKYBRIDGE/name` 저장소의 주인 및 성씨 `서(徐)`를 중심으로 체계적인 개명을 연구·비교하려는 사용자.
- **핵심 가치**: 흩어져 있는 사주, 81수리, 획순, 음양오행, 발음오행, 자원오행 검증을 매번 수작업으로 계산하지 않고 한 화면에서 실시간 대조·저장하며, 개인이 정리한 마크다운/JSON 작명 노트까지 엔진에 직접 결합할 수 있습니다.

## 2. 사용자 경험(UX) 및 시각 디자인

### 핵심 사용자 플로우

1. **사주 및 기존 이름 설정 (초기 진입 / 상단 프로필 바)**
   - 양력/음력(윤달 포함), 생년월일시(시간 모름 옵션 포함), 성별, 기존 이름(한글 + 한자 선택)을 입력합니다.
   - 성씨는 **천천히 서(徐 · 원획 10획 · 필획 10획 · 발음오행 金 · 음양 陰)**로 기본 고정되며, 필요 시 서씨 세부 해석 기준(원획법/필획법, 중성 오행 반영 여부 등)을 전환할 수 있습니다.
   - 입력 즉시 사주팔자 4기둥(년·월·일·시주) 천간·지지, 목·화·토·금·수 오행 분포 막대, 용신·희신 추천이 계산됩니다.

2. **개명 후보 추천 및 맞춤 조합 (작명 스튜디오)**
   - **자동 추천 모드**: 사주 용신과 `서(徐)` 성씨의 발음오행(金) 상생(예: 金→水→木, 土→金→水 등) 및 원격·형격·이격·정격 4격 모두가 81수리 길수(吉數)에 들어맞는 이름 후보를 자동 산출합니다.
   - **직접 조합 모드**: 원하는 한글 발음(예: 서윤, 서우, 서준, 서현 등)을 입력하면 음령오행 적합도를 먼저 판정하고, 각 글자에 들어갈 수 있는 대법원 인명용 한자를 획수·자원오행·뜻풀이별로 필터링해 실시간으로 4격 수리를 시뮬레이션합니다.

3. **기존 이름 vs 개명 후보 비교 감정 (비교 리포트)**
   - 좌측에 **기존 이름**, 우측에 **선택한 개명 후보**를 나란히 배치하여:
     - 초년운(원격)·청년운(형격)·중년운(이격)·말년운(정격) 81수리 변화
     - 음양 조화(예: 陰-陰-陰 흉격 → 陰-陽-陰 길격 개선)
     - 발음오행 상생 흐름 및 자원오행의 사주 용신 보완도
     - 불용한자(이름에 피해야 할 한자) 포함 여부 및 획순(필순) 안내를 한눈에 대조합니다.

4. **AI 작명가 심층 해설 및 내 자료 연동 (지식 동기화)**
   - 선택한 이름 후보에 대해 **정통 성명학 계산 결과 + 사용자가 불러온 `name` 저장소 노트**를 컨텍스트로 전달하여, 어감의 세련됨·한자 뜻의 조화·개명 방향성을 자연스러운 한국어 리포트로 풀이합니다.
   - **내 자료 연동 패널**: `LUCKYBRIDGE/name` 저장소의 정리 파일(특히 서씨 관련 노트, 선호 한자 CSV/JSON/MD)을 업로드하거나 붙여넣어 사용자 정의 한자 사전과 감점/가점 규칙을 즉시 반영하고 저장합니다.

### 시각적 아이덴티티 및 레이아웃 규칙

- **미학적 방향**: 과장된 점술/무속 테마나 네온 다크 대시보드를 배제하고, 고전 서책과 현대 정밀 분석 도구가 결합된 **아카이브 한지 에디토리얼 스튜디오** 톤을 유지합니다.
- **색상 시스템 (60-30-10)**:
  - **60% 바탕**: 따뜻한 한지 미색 (`#FBF9F5`)
  - **30% 구조 표면**: 담백한 백자 카드 (`#FFFFFF`) 및 먹선 헤어라인 경계 (`#E7E2D8`), 본문 먹색 (`#1C1917`), 보조 회색 (`#57534E`)
  - **10% 강조 및 오행 토큰**: 인주(朱) 포인트 (`#9A3412`)를 핵심 액션에 집중하고, 오행(木 청록·火 적주·土 황토·金 백은·水 남청)은 색맹 접근성을 위해 **반드시 한자/한글 라벨(예: `木 목`)과 함께** 표기합니다.
- **타이포그래피**:
  - 한자/이름 디스플레이 및 제목: `Noto Serif KR` (단아한 명조 계열, 자간/행간 여유)
  - UI 및 본문 분석 텍스트: `Pretendard` / `Noto Sans KR`
  - 획수·81수리·오행 비율·사주 연도 수치: `JetBrains Mono` (`tabular-nums` 적용으로 수직 정렬 유지)
- **레이아웃 원칙**:
  - 상단 3영역 내비게이션 바(브랜드 워드마크 — 4개 단일 줄 탭: `사주·성씨 분석` / `개명 작명소` / `이름 비교 리포트` / `저장소 자료 연동` — `후보 보관함` 버튼).
  - 정적 메타데이터에는 둥근 알약 배지(Pill)를 쓰지 않고 `·` 또는 `/` 구분 텍스트로 정갈하게 표기합니다.

## 3. 주요 제품 결정 및 트레이드오프

- **결정 1: 결정론적 성명학 계산 엔진 + AI 해설 분리 아키텍처**
  - *선택한 방식*: 81수리 계산, 원획/필획 판정, 음양 배합, 한글 초성 발음오행, 사주 오행 산출은 100% 결정론적 TypeScript 엔진으로 계산하고, Gemini API(`gemini-4-hydrogen`)는 계산된 수치를 바탕으로 한자 뜻풀이 조합·현대적 어감·종합 개명 조언을 작성하는 데만 사용합니다.
  - *이유*: AI가 한자 획수나 81수리를 임의로 착각하는 오류를 원천 차단해 성명학적 정확도를 보장하기 위함입니다.
  - *대안 검토*: 모든 작명을 LLM 프롬프트에만 의존하는 방식은 수리 계산 오류가 잦아 배제했습니다.

- **결정 2: 비공개 GitHub 저장소(`LUCKYBRIDGE/name`) 대응 로컬/브라우저 동기화**
  - *선택한 방식*: 서버에 인증 토큰을 요구하지 않고도 앱 내 **저장소 자료 연동** 탭에서 Markdown/JSON/CSV/TXT 파일을 업로드하거나 공개 GitHub URL을 조회해 파싱·병합할 수 있도록 설계하며, 결과는 로컬 저장소(`localStorage`) 및 서버 내보내기/불러오기로 유지합니다.
  - *이유*: 계정 보안을 위해 저장소를 비공개로 유지하면서도 사용자가 공들여 정리한 `서(徐)` 성씨 자료를 손실 없이 즉시 활용할 수 있습니다.

- **결정 3: '천천히 서(徐)' 성씨 전용 규칙셋 특화**
  - *선택한 방식*: 일반 범용 작명소와 달리, 서(徐)씨의 고정 변수(초성 `ㅅ`=金, 원획 10획=陰, 부수 `彳`·음 `余`의 자원오행 및 의미적 확장성)를 기준점으로 두고 발음오행 상생 매트릭스(金→水, 土→金 등)와 사주 보완 조합을 우선 가중치로 노출합니다.
  - *이유*: 사용자가 저장소에 별도로 정리한 `성씨 천천히 서` 맥락을 도구의 핵심 정체성으로 살리기 위함입니다.

### 데이터 모델 및 상태 매핑

- **사주 프로필 상태 (`BirthProfile`)**: 양력/음력 여부, 생년월일시, 성별, 기존 이름(한글/한자/획수), 산출된 천간·지지 8자, 오행 비율(`목/화/토/금/수`), 부족 오행(용신/희신).
- **성씨 규칙 (`SurnameConfig`)**: 기본값 `서(徐)` — 원획 `10`획, 필획 `10`획, 발음오행 `金`, 자원오행 `土/金`, 음양 `陰`, 사용자 커스텀 메모 및 가중치 오버라이드 지원.
- **한자 사전 (`HanjaEntry`)**: 한자, 음(훈음), 원획수, 필획수, 자원오행, 부수, 불용문자 여부, 현대 선호도 태그, 획순(필순) 설명 및 획순 애니메이션/가이드 정보. (초기 내장 인명용 한자 300+선 + 사용자 자료 업로드로 무제한 확장 가능)
- **작명 후보 및 비교 상태 (`NameEvaluation`)**: 성+이름 3자 조합에 대한 4격 수리(원·형·이·정격 + 81수리 길흉 해설), 음양 배열, 발음오행 상생/상극 그래프, 자원오행 사주 보완 점수, 즐겨찾기 보관함(`SavedCandidate[]`), 기존 이름과의 비교 스냅샷.

### 주요 상호작용 핸들러 매핑

- **프로필 폼 변경**: 입력 검증 후 즉시 만세력 오행·용신 및 기존 이름 감정 결과를 재계산하여 대시보드와 비교 리포트에 반영.
- **개명 작명소 필터(용신 오행, 81수리 최소 길격 등급, 발음오행 상생 필수 여부, 불용한자 제외, 선호 돌림자/글자 지정)**: 실시간 클라이언트 필터링 및 정렬, 빈 결과 시 완화 필터 제안 버튼 제공.
- **저장소 자료 가져오기(Upload / Paste / GitHub Sync)**: Markdown 헤딩·테이블이나 JSON/CSV 구조를 파싱해 `서(徐)` 특화 규칙·추가 한자·금기 한자를 즉시 병합하고, 적용된 항목 수를 화면에 피드백.
- **AI 심층 해설 요청**: Express `/api/naming/interpret` 호출 중 로딩 스켈레톤 표시, 오류 시 재시도 안내 및 결정론적 계산 결과는 항상 즉시 열람 가능하도록 분리.
